# Психотесты — каталог тестов онлайн

Next.js (App Router) + TypeScript + Tailwind CSS. Без бэкенда и базы данных: тесты — JSON-файлы в `data/tests`, результаты считаются в браузере и хранятся только в `localStorage`. Деплой: Vercel (импортировать репозиторий, настройки по умолчанию).

```bash
npm install
npm run dev        # http://localhost:3000
npm run validate   # проверка всех JSON в data/tests (Node 22.18+)
npm run build
node scripts/engine-check.mjs   # проверки подсчёта на крайних ответах
npm run e2e        # UI-тесты и проверка доступности (Playwright + axe); локально: PW_CHANNEL=msedge npm run e2e
```

## Структура

```
app/
  page.tsx                  главная: поиск, категории, популярные
  tests/[id]/page.tsx       карточка теста
  tests/[id]/run/           прохождение (один вопрос на экран)
  tests/[id]/result/        результат (?r=<id записи из истории>)
  results/                  «Мои результаты»
  about/                    «О проекте»
components/
  Catalog, Runner, ResultView, Charts (радар и полоса, SVG), HelpBlock, HistoryList, ...
lib/
  types.ts      схема теста (TypeScript)
  engine.ts     универсальный подсчёт и проверка правил безопасности (чистые функции)
  validate.ts   проверка JSON при сборке
  tests.ts      загрузка data/tests/*.json
  storage.ts    localStorage: прогресс и история
  exportPng.ts  PNG-карточка результата на canvas
data/
  tests/*.json  тесты
  helplines.json контакты помощи по странам
```

## Как добавить новый тест

1. Создайте `data/tests/<id>.json`; **имя файла = `id`**. Скопируйте за образец `rosenberg-self-esteem.json` (одна шкала), `ipip-big5-50.json` (подшкалы) или `phq-9.json` (клинический, с правилами безопасности).
2. Заполните поля (схема в `lib/types.ts`):

| Поле | Значение |
|---|---|
| `status` | `"ready"` — можно проходить, `"draft"` — только карточка («Скоро») |
| `category` | `personality`, `emotional`, `wellbeing`, `relationships`, `eq`, `career`, `neurodiversity`, `values` |
| `scale.options` | варианты ответа `{value, label}`; одинаковы для всех вопросов |
| `questions[]` | `{id, text, reversed?, subscale?, scoreWhen?}`. `reversed` инвертирует значение: `min + max − ответ`. `scoreWhen: [значения]` — дихотомический ключ: 1 балл, если выбран один из этих вариантов (AQ-10) |
| `scoring.method` | `sum`, `average` (одна шкала `total`), `subscales`, `typeMax` (подшкалы + доминирующий тип) |
| `scoring.aggregate` | для подшкал: `sum` (по умолчанию) или `average` |
| `scoring.subscales` | `[{id, title}]`; у каждого вопроса должен быть `subscale` |
| `interpretation` | ключ — id подшкалы или `total`; значение — диапазоны `{min, max, title, description, level?}`. Берётся последний диапазон, у которого `min ≤ балла`, поэтому для дробных средних дыр не бывает |
| `isClinical`, `safety` | см. ниже |
| `source`, `license`, `author`, `year` | обязательны: показываются в карточке и на странице «О проекте» |
| `translationNote` | если перевод рабочий/не валидирован — скажите об этом |
| `todo` | список того, что осталось проверить (для заготовок) |

3. Запустите `npm run validate`. Проверяется: совпадение `id` с именем файла, уникальность `id` вопросов, `questionCount`, ссылки на подшкалы, наличие `interpretation` для каждой шкалы, ссылки в `safety`. Сборка (`npm run build`) падает при ошибке.
4. Больше ничего менять не нужно: тест появится в каталоге, получит страницы описания, прохождения и результата.

### Клинические скрининги

Поставьте `isClinical: true` и опишите правила:

```json
"safety": {
  "helpAboveScore": { "scale": "total", "min": 10 },
  "crisisQuestions": [{ "questionId": "q9", "above": 0 }]
}
```

- `helpAboveScore` — мягкий блок «обратитесь к специалисту» с контактами при баллах ≥ `min`.
- `crisisQuestions` — блок экстренной помощи, если **сырой** ответ на вопрос больше `above` (в PHQ-9: любой ответ, кроме «ни разу», независимо от общего балла).
- На каждой странице результата дисклеймер «Тест не является диагнозом…» выводится всегда.

### Правила для содержимого

- Только открытые методики. Проприетарные (MMPI, MBTI, NEO-PI-R, Beck, MBI, Роршах) не добавлять.
- Формулировки и ключи брать из первоисточника или валидированной адаптации. Не уверены — оставьте `status: "draft"` и запишите в `todo`, а не придумывайте.
- Если схемы не хватает (формулы OEJTS, пороговый подсчёт ASRS, центрирование PVQ), расширьте `lib/types.ts` и `lib/engine.ts`, а не добавляйте код под конкретный тест.

## Аналитика ответов

На странице результата каждого теста (в том числе в режиме ввода ответов) под интерпретацией показан блок «Аналитика ваших ответов»: текстовые выводы (самый частый вариант, доля крайних и нейтральных ответов, предупреждение об одинаковых ответах), распределение ответов, график ответов по ходу теста и вклад каждого пункта в результат (полосы с текстом или матрица для длинных тестов, с переключением «по порядку / по вкладу»). Распределение ответов попадает и в PNG. Логика — в `lib/analytics.ts`, графики — в `components/AnswerAnalytics.tsx`; проверяется e2e-тестом для каждого готового теста.

## Глубинный анализ

Вкладка «Глубинный анализ» на странице /profile учитывает **все пункты всех пройденных тестов**. Модель (`data/dimensions.json`) связывает каждую шкалу с 23 скрытыми характеристиками (шесть черт, три измерения эмоционального состояния, самооценки, благополучие, привязанность, круг отношений, интересы и др.) через нагрузки от −1 до 1; отдельные пункты могут иметь свои нагрузки (`itemLoadings`, например пункт PHQ-9 о самооценке).

Расчёт (`lib/deep.ts`): пункт оценивается в направлении своей шкалы (обратные пункты инвертированы), затем для каждой характеристики пункты объединяются взвешенным средним внутри теста, а результаты тестов — по модели случайных эффектов (DerSimonian & Laird, 1986). Показываются итог, интервал, число пунктов и тестов, неоднородность I² (Higgins & Thompson, 2002), «косвенность» оценки (нет прямой шкалы) и пункты, подтверждающие итог или идущие против него. Над скрытыми характеристиками строятся метачерты (Digman; DeYoung), круг Виггинса, трёхфакторная структура эмоций (Clark & Watson), оси интересов (Prediger) и упрощённый прототип по Блокам. Правила выводов — `lib/deepInsights.ts`.

Важно: нагрузки назначены экспертно (по определениям шкал, литературе и содержанию пунктов; основание указано в поле `b`), а не оценены по данным: по ответам одного человека факторный анализ невозможен. Проценты — положение на шкале, не нормы; интервалы прикидочные. Список работ, на которых основана модель, показан на самой вкладке («Научная основа»). Проверка полноты (`npm run validate`) гарантирует, что каждая шкала каждого готового теста входит хотя бы в одно измерение.

Чтобы добавить новую шкалу в модель, внесите её в `loadings` нужных измерений в `data/dimensions.json` (теста может не быть в списке — проверка это обнаружит).

## Целостный профиль

Вкладки страницы /profile: «Целостная картина», «Сводные таблицы», «Диаграммы». Шкалы из разных тестов, которые измеряют одно и то же, объединяются в сводные показатели по соответствиям из `data/constructs.json` (например, «Экстраверсия» = IPIP-50, Mini-IPIP, TIPI и HEXACO-60; «Эмоциональная устойчивость» = перевёрнутый нейротизм из тех же тестов). У каждого соответствия есть `weight` (1 — прямое, меньше 1 — родственное) и `invert` (противоположный полюс).

По каждому показателю считаются: итог (взвешенное среднее положений на шкалах), диапазон между тестами, согласованность (до 20 п. п. — согласуются, до 35 — умеренный разброс, больше — тесты расходятся), уверенность (число тестов и согласованность). Выводы о сочетаниях показателей (`lib/insights.ts`) строятся по простым открытым правилам и сформулированы осторожно, без диагнозов. Радары с наложением показывают итог и контуры отдельных тестов; таблицы — итог с разбросом, матрицу «тест × характеристика» и сортируемый список всех шкал.

Чтобы связать новую шкалу с показателем, добавьте её в `sources` нужного конструкта в `data/constructs.json` и запустите `npm run validate` (проверяются тест, шкала и вес).

## Профиль

Страница /profile строит диаграмму из последнего прохождения каждого теста: каждая шкала — одна «характеристика». Три вида: круговая карта (все характеристики сразу, цвет — категория), радар (3–16 осей) и полосы по категориям. Можно выбирать, что показывать (скрининги по умолчанию выключены), выбор сохраняется в localStorage, диаграмма скачивается как PNG или PDF. Значение — положение на шкале конкретного теста (0–100 %), а не норма и не сравнение между тестами. Данные не покидают браузер.

Готовы 26 тестов (22 проходятся на сайте, 4 — в режиме ввода ответов):

- Личность: Big Five (IPIP-50), Mini-IPIP (20), TIPI (10), SD3

- Отношения: ECR-R, UCLA-3
- Эмоциональный интеллект: ERQ (регуляция эмоций)

- Профориентация: RIASEC (O*NET)

Русские тексты PHQ-9, GAD-7, GSE и DASS-21 — опубликованные версии (авторы и источники в карточках). У остальных — рабочие переводы, не валидированные адаптации; это указано в карточке каждого теста.

## Режим ввода ответов (mode: external)

Для тестов, чьи вопросы нельзя воспроизводить на публичном сайте (HEXACO-60, AQ-10, PSS-10, ASRS), вопросы не показываются. Пользователь проходит тест на сайте оригинала (ссылка в карточке), вводит номера своих ответов (по пунктам, строкой через пробел или запятую, либо файлом .txt/.csv), а сайт считает результат по опубликованному ключу и объясняет его. Формат: в JSON `"mode": "external"`, поле `external` (`url`, `urlLabel`, `note`), у вопросов `text` вида «Пункт N» и только ключ (`reversed`, `subscale`, `scoreWhen`).

Это не отменяет условия правообладателей на сам тест: в карточке указано, что вопросы здесь не воспроизводятся. Для HEXACO-60 авторы разрешают бесплатное использование только в некоммерческих исследованиях, поэтому пользователь проходит опросник на hexaco.org на их условиях.

## Что проверить перед широкой публикацией

- Лицензии с пометкой TODO в карточках тестов.
- Контакты помощи в `data/helplines.json`.
- Пороги интерпретации Big Five, Grit-S, ECR-R, RIASEC, TIPI, ERQ, LOT-R, Flourishing, GSE и BRS — ориентировочные, не нормы.
- PDF — через печать браузера («Сохранить как PDF»), PNG — canvas-карточка с баллами, радаром и интерпретацией.
